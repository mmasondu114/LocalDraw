# LocalDraw 本地漫画工作室

LocalDraw 是 Windows x64 桌面应用，支持创作漫画、编辑分镜，以及从每格提示词直接出图。

## 下载和安装

登录有仓库访问权限的 GitHub 账号。新电脑从[首次安装包](https://github.com/mmasondu114/LocalDraw/releases/tag/v0.1.1)安装，已有安装从[最新发行版](https://github.com/mmasondu114/LocalDraw/releases/latest)下载程序更新。

- **首次安装**　把四个以 `.001` 至 `.004` 结尾的文件和 `Join-LocalDraw-Setup.cmd` 下载到同一个文件夹。双击命令文件，等它确认安装程序校验通过，再运行合并得到的 EXE，选择空目录安装。此包面向 Windows x64、RTX 4080 环境。首次出图需要在应用中点「下载模型」，或使用已安装的模型。
- **更新已有安装**　等当前任务结束后关闭工作室，将对应版本的 `Update.zip` 解压到含有 `LocalDraw.exe` 的目录并覆盖程序文件。重启电脑后打开工作室，以加载新的后台程序。此更新包适用于已安装 RTX 4080 完整版的电脑。

## 预加载绘图模型

顶部「绘图模型」可选择已安装的底模并提前加载。连续使用同一底模出图时工作室会保留绘图服务。再次选中已加载的模型可卸载并释放显存，选中其他模型可切换。启动分析模型或暂停生成时会释放预加载。

更换同一底模下的角色、LoRA 或权重，直接修改下一次出图的设置即可。新提示词和逐格导入会优先使用已预加载的底模。逐格导入缺少编辑参考图，因此会跳过专用的 Qwen 编辑模型。

## 从每格提示词开始

首页「提示词出图」先创建分镜作品。填写标题，可选填故事构想或期望的页数。点击「生成分镜」，本地分镜模型会规划每页画格、画面内容和比例。预览后点击「确认分镜并进入出图」。在正向提示词框粘贴带编号的单格 JSON，如 `{"id":"P001-K01","visual_prompt":"rainy train station","negative":"watermark"}`。工作室按编号定位并默认使用该格分镜比例。纯文字提示词可手选画格。角色、LoRA、张数和比例都可在提交前调整。

在候选图下点「采用到 P001-K01」，这张图就成为该格的选图。采用同格的另一张会替换选图，「取消采用」保留候选原图。「整图修改」会列出尚缺的格子；全部采用后，可调整各页版式及裁切方式，生成并下载整页 PNG。

在首页点「直接导入每格提示词」，粘贴内容后点「导入并设置出图」。在设置页选择角色、LoRA 和默认张数，也可以填写通用负面提示词。展开「逐格编辑负面提示词和张数」可以修改某一格。生成时会将通用负面提示词追加在本格负面提示词之后。点「开始生成」提交任务，选「稍后再画」可以从作品旁的「出图设置」继续。

使用 Anima Delta v6 和 AnimeEditV2、且本次至少有两格时，设置页默认勾选「自动参考上一格」。第 1 格独立生成。后续每格使用上一格在本次任务中最先成功生成的图片作为参考，跨页也会接续。取消勾选即可让各格独立生成。

逐格 JSON 的一页一格示例：

```json
[{"id":"P001-K01","visual_prompt":"雨夜街口，远景","negative":"水印，多余文字"}]
```

在「提示词出图」和「融合任务」逐格审核中，勾选「正负面同框（JSON）」即可在同一个框中编辑 `visual_prompt` 和 `negative`。「复制本格 JSON」会复制可直接导入的一格。在「直接导入每格提示词」中可复制给 AI 的格式要求；在「逐格出图设置」中可复制全部画格，含当前编辑的负面词和通用负面词。

## 融合任务

在首页或「夜间任务列表」点「融合任务」，依次添加至少两部已有分镜的作品或队列任务。用「上移」「下移」决定拼接顺序，再逐格核对正面和负面提示词。可以跳过不想画的格子，再用「恢复此格」取回。改过的画格需要重新点「通过并继续」。点「稍后继续」会在当前浏览器保留审核进度。逐格审核完后点「保存融合任务并设置出图」，会创建独立的新作品，并进入角色、LoRA、张数和连续参考设置。新作品使用审核过的提示词重新出图，原作品和队列任务可照常使用。

## 检测更新

点击窗口顶部的「检测更新」。工作室将当前版本与私有仓库的最新正式发行版比较。本机已登录的 GitHub CLI（在 PATH 中）或 `GH_TOKEN` 可用于查询。也可以在弹窗里填写此仓库具有 Contents 只读权限的 GitHub 令牌，令牌仅用于本次查询。「打开 GitHub 下载页」使用系统浏览器里的 GitHub 登录状态。

## 源码与运行环境

`src/comic_workflow` 是本地服务，`web` 是界面，`scripts/windows` 包含桌面启动器源代码。安装包提供配套的 Python、绘图运行时和桌面组件。可在已安装的运行环境中替换源码进行开发。开发环境使用 Python 3.12，通过 `PYTHONPATH=src` 运行对应测试。

桌面发行版的完整项目在 `LocalDraw/`。根目录保留开发版源文件、工具和历史开发说明。

# 本地漫画工作室

## Windows 桌面版

双击根目录的 `LocalDraw.lnk` 或 `LocalDraw/LocalDraw.exe`。在首页点「直接导入每格提示词」，粘贴或选择 TXT（每行一格）或逐格 JSON，再点「导入并设置出图」。在设置页选择角色、LoRA 和每格张数，点「开始生成」提交。旧桌面版和独立网页入口位于 `archive/2026-11-20/`。

22 个旧批处理入口集中在 `archive/legacy-launchers/`，3 份历史说明在 `archive/notes/`，移动记录和校验值见 `archive/manifest.json`。旧辅助脚本已修正相对路径。构建方式与验证记录见 `docs/DESKTOP.md`。

## 默认创作视角（2026-11-05）

后续创作、分镜和绘图提示词默认采用 **POV 第一人称视角**，不使用双人构图。除非用户明确提出其他要求，均遵循此偏好。

## Krea2 与 MOSS 高精度出图（2026-10-24）

“提示词出图”、漫画绘图设置和导入提示词的模型列表已加入 **Krea2 Turbo · BF16 高精度** 与 **MOSS-Image SFT · BF16 高精度**，可直接出图或加入任务列表。Krea2 默认 8 步，不使用负面提示词；MOSS 默认 25 步、CFG 2.5，使用独立的 Qwen3.5 9B 编码器和 Flux2 VAE，图片尺寸按 16 像素对齐。Krea2 FP8 仍可选择，默认模型仍是 Anima Delta Mix v6。

LoRA 按模型架构过滤：Krea2 使用 `models/loras/krea2`，MOSS 使用 `models/loras/moss_image`；不会混入 Anima 或 SDXL 权重。两者使用文字与同架构 LoRA，不启用现有 SDXL 参考图、分区控制或手部修复。工作室改用 `runtime/ComfyUI-KreaMoss` 和 `runtime/kreamoss-venv`，在 CUDA 上计算并按需将权重暂存到系统内存，支持 24GB 显卡加载 Krea2 BF16。原后端配置备份在 `runtime/kreamoss-frontend-backup/comfyui.json`。

## 页面加载与暂停任务数量（2026-10-23）

首页直接显示，漫画绘图模块按需加载。角色库和绘图选项在当前页面复用 30 秒，编辑角色或 LoRA 标注后立即失效；作品列表使用独立轻量接口。切换作品并行读取作品和草稿，任务状态、图片和作品内容不使用这份公共资料缓存。暂停任务不再重建整个绘图表单。

暂停的逐格绘图任务中，左侧和绘图区的每格数量同步，选择后自动保存。点击继续会等待数量保存成功；保存失败不会继续旧参数。数量表示未完成格的目标总数：8 改 4 后，已有 1 张的格只补 3 张；已有 5 张的格保留全部 5 张，不再追加；已完成格不补画。重启后的继续任务与设置界面共用同一份参数，后续暂停修改也能生效。旧任务已保存的排程保持原样，直到明确修改数量。

## 开始页与夜间任务列表（2026-10-22）

打开工作室后，可以选择「提示词出图」「创作新漫画」或「夜间任务列表」，也可继续已有作品。左侧「开始 / 创作指南」随时返回入口；首页会显示正在运行或等待继续的任务。

右上角「界面显示」可切换标准字号与大字号，浏览器会记住选择。提示词页面的立即出图和加入列表固定在输入区下方；清空提示词、角色和 LoRA 后可撤销。空白图片区提供可自由修改的示例。漫画所有画格选图完成后，选图区上方会出现「选好了，查看成品」。

在提示词出图、漫画第三步的出图确认或导入提示词区，点击加入任务列表。可以连续添加不同任务、调整等待顺序、移除项目，再立即开始或预约未来 30 天内的时间，也可点「1 小时后」快速填写。列表显示执行顺序及待画张数，顶部可直接添加提示词任务；加入成功后，表单下方会保留打开列表的入口。默认遇到失败暂停列表；取消该选项可继续后面的任务。暂停列表会让当前任务正常做完，具体任务的暂停或结束仍使用工作台顶部按钮，已暂停的排队任务也能在列表直接继续。

任务列表采用竖向时间轴，每项任务为横向卡片，从上到下依次执行。顶部和时间轴末尾都有「添加任务」，可选择提示词或已有漫画；从这里添加成功后会自动回到时间轴并定位新卡片。左侧显示顺序与开始时机，卡片可上下移动、查看保存的设置、打开作品或移出列表。工作台已有任务会显示在时间轴前面，等待它结束后再执行排队任务。

滚动时间轴时，顶部的添加任务和关闭按钮始终可见。运行进度只更新卡片内的文字和进度条，不会打断正在使用的卡片按钮；当前工作台任务也显示已完成数量，有运行估算时显示本阶段预计剩余分钟。

工作台顶部的任务按钮在进度刷新时保持原位，暂停、继续和结束会随实际状态切换可用性。「查看运行详情」展开后保持展开；后台连接中断时保留最后进度并禁用任务操作，连接恢复后更新为真实状态。

提示词任务和漫画范围设置可填写可选任务名称，留空时自动命名。已有卡片的「改名称」只修改时间轴名称，保存后刷新和重启仍保留；不会改动出图参数或作品名。

从时间轴返回提示词表单继续添加时，会保留当前文字、张数、模型与 LoRA。漫画加入列表前可选择未选图画格、整部漫画、某一页或单格，单独指定每格数量，再确认逐格提示词；选择已完成的范围会追加新候选，保留原有图片及选图。

提示词输入自动保存为当前浏览器中的草稿，包括正负提示词、模型、张数、比例、任务名、角色外观和位置，以及选中的 LoRA 与强度。刷新后重新进入可恢复，已保存作品各自保留独立草稿；清空内容也会保存为空，并可立即撤销。从首页返回仍打开的提示词页会保留当前预览。草稿只保存输入设置，临时预览图片仍需另行保存，加入队列的作品图片则由后台保存。

新漫画的空白剧本页提供三步指引和三个英文故事示例，示例只填入文字，不自动运行模型，也不覆盖已有输入。生成按钮跟随整理、扩写、续写模式变化，并提示空白或任务忙碌状态。故事框旁的「展开编辑」提供大窗口，点击完成后填回工作台，取消会保留原文。

加入时保存提示词、模型、数量和 LoRA 设置，后续改动不会改写已排队的设置；漫画分镜或角色资料发生变化时，旧任务会停止并提示重新确认。提示词排队作品及图片保存到作品库，普通立即出图仍是临时预览。重新排队会复用这项任务已经保存的图片，只补缺少的部分；从表单重新加入属于一个新任务。

关闭网页后后台继续运行，电脑必须保持开机、不休眠。任务列表写入 `data/night-queue.json`；重新启动工作室后保留列表但不自动开始，中断的任务需先核对工作台中的恢复状态。移出列表保留作品和图片。清空已保存的排队作品图片时，会先移入该作品的 `cleared-images` 备份目录。

失败、部分失败和重启后待核对的任务会集中在「需要处理的任务」，显示原始原因和恢复说明。点击「重新排队」后自动定位回到时间轴上的卡片；列表未开始时仍需手动开始。即使旧任务记录文件缺失，也能使用队列保存的原参数恢复，绘图前仍会核对未确认的提交并复用已有结果。正在执行、暂停或已经继续的原任务须先在工作台处理，不能重复排队。

## 默认气泡语言（2026-10-18）

新生成的对白、旁白、拟声与 `lettering.text` 默认使用简体中文；用户明确要求其他语言时按其要求。人物、场景和绘图描述及正负绘图提示词继续使用英文。已导入的原始剧本保留原文，现有作品的文字需明确要求后才翻译。

成品查看、PNG 和可编辑 SVG 的文字统一横排，按气泡宽度自动换行。每格气泡按对白顺序从上往下排列，左右两侧共用一个纵向顺序。横向位置优先匹配说话人，兼容中文“左／右”和英文“Left／Right”；手动横向位置与逐句 AI 的左右位置仍有效，纵向位置不能颠倒对白顺序。

暂停任务时，默认先完成并保存当前工作单元，再卸载模型、释放显存。点击继续会自动重新加载所需模型，并接着已有进度执行；暂停期间取消不会重新加载模型。若绘图队列仍有任务或卸载失败，任务保持暂停并显示原因，已有结果保留。

## 默认绘图模型（2026-10-18）

后续新任务默认使用 **Anima Delta Mix v6**（`animaDeltaMix38BQwen0_deltaMixV60.safetensors`），默认 35 步、CFG 4.5、`dpmpp_2m` / `sgm_uniform`。新作品及未单独保存模型的作品、直接提示词入口共用 `config/comfyui.json`；已有明确模型选择及已提交任务快照仍使用其保存值。

第三步「分镜提示词 → 导入出图设置」支持选择整页范围，以及一张本作品候选图作为固定参考，并显示缩略图。仅 Anima Delta v6 支持；不选择时保留原提示词直出行为。选择后加载 Anima Edit v2 与 Cosmos 图像参考，正负提示词保持原文。同一范围内每格串行生成，固定参考按内容哈希保存到任务快照，暂停、继续和后续换选图不会改变任务的参考。参考图等比例缩放并补边到当前格尺寸，满足本地参考节点的尺寸要求。它辅助保持人物、服装、道具外观，也可能牵制构图，不保证细节完全一致；一次只使用一张参考图，不等同于多人分别绑定参考。

## 第三阶段本地填写提示词（2026-10-18）

第三步「分镜提示词」新增「本地 Qwen 自动填写提示词」。使用已配置的本地 Qwen，以当前格完整资料和相邻格的动作、镜头为依据，逐格生成英文正负提示词；每格完成即保存到作品的 `local-prompts/`，不改写原分镜或覆盖已确认提示词。

点击按钮后使用 GPU 推理，沿用工作室现有的语言模型加载流程：确认绘图队列空闲后释放绘图模型，为 Qwen 腾出显存。正常结束、失败和取消均卸载语言模型，暂停时卸载、继续时重新加载。进度显示实际完成格数；可在顶部暂停、继续或取消。服务重启后暂停任务可继续，复用已完成的格；分镜变化时拒绝沿用旧草稿。此功能的开发验证使用模拟模型和离线测试，不启动真实 GPU 推理。

完成后点击「核对本地草稿」，可编辑每格提示词，点击「确认使用」才保存到现有提示词导入流程，之后自行点击绘制。未完成的草稿也可核对已完成部分，漏格会明确列出。关闭核对窗口不会应用草稿，不会自动出图。外部 JSON 的导出、导入仍可使用。

## 完整剧本 JSON 导入（2026-10-18）

左侧「导入剧本 JSON」或第一步「已有完整分镜？导入剧本 JSON」可读取包含 `brief`、`canon`、`pages` 数组的整部剧本文件，兼容《Your Break Is Ready》的六页分镜文件。可选 `format` 为 `local-draw-story-v1`，结构见 `schemas/story_import.schema.json`；文件最多 5 MB，支持 UTF-8 BOM。

选择文件后先预览标题、角色、页数、逐格画面和对白。点击「导入为新作品」后进入第二步分镜编辑；原有作品、图片和编辑草稿保留。不调用语言模型，不自动翻译、改写、绘图或选图。页面、人物与道具引用、气泡编号、版式和页间状态必须完整有效，错误会指出位置并阻止保存；普通分镜提醒仍可展开核对。

`pages` 必须包含全部页面，从 `P001` 顺序排列，页数与 `brief.page_count` 一致。每页沿用 `schemas/page.schema.json`，对白保存在该页 `lettering`，不放进 `panels`。程序从现有分镜整理内部大纲、分页计划及阅读文本，原始输入另存在新作品的 `story-import/source.json`。角色资料与分镜原样保留；按准确同名关联本地角色卡快照，文件携带的角色卡附件引用不直接载入，也不会修改公共角色库。同名卡片在预览后发生变化时须重新预览。

此入口不接收单页 `P001.json`、外部绘图提示词文件或导出的完整作品备份 `script.json`。绘图提示词仍使用第三步的「外部提示词」入口。保存采用完整写入后发布；重复提交同一次导入会返回同一作品。

英文对白长度提醒按每气泡 25 个单词、每格全部文字 55 个单词计算，旧中文内容继续使用原字数提醒。

## 分镜差异与角色归属核对（2026-10-17）

分镜导出文件现在附带本格可见角色的外观资料和逐格编写规则：镜头、人数、动作在前，人物属性分别归属，不把双人描述套入单人特写。普通出图确认、外部提示词导入预览及已导入记录会提示相同提示词、过长共用开头、中英混写、非出镜角色被写入正向描述，以及当前模型未启用专属 LoRA 的角色。确认区列出分镜人物、景别及实际匹配的 LoRA。检查只提示，不改写用户文本，不自动增加模型调用、审核或补画。

候选数量仍只改变随机种子。角色 LoRA 绑定决定按谁的出场记录加载，不代表多人特征已被空间隔离。2026-10-17 的独立非露骨短篇对照使用 Qwen3.8-27B Q5 与 Delta Mix v6：按格英文描述改善了单人/双人和景别差异，但远景仍存在额外人物、光环串位和动作偏差，不能作为整部漫画人物一致性的保证。样图、工作流、GPU 记录位于 `data/test-results/panel-identity-20261017/`；旧作品和已确认提示词未改写。

区域条件的后续验证修正了全图与局部人物描述同时叠加的问题：局部条件仅覆盖对应人物，背景使用默认条件填补未覆盖区域。双人中景的三个种子均未见耳朵、光环或发色串位，但一张出现两个信封，递交动作仍有偏差。远景的小区域会漏人，扩大区域后仍可能出现过大的前景人物和额外路人；区域裁切还可能使人物与建筑融合。不能据此宣称整部人物一致性已修复，实验未接入普通出图。

另有 Anima 专用注意力区域试验：仅验证脚本通过 `anima_regional_trial` 加载 `Comfyui-Anima-Regional-Conditioning`，普通启动默认不加载。上游固定版本、文件哈希、当前 ComfyUI 接口兼容补丁与逐次运行结果保存在上述实验目录；没有安装新模型权重。报告由 `scripts/build_panel_identity_report.py` 从人工检查记录生成，所有尝试须检查后才能发布，运行成功与画面验收分别记录。

## 当前出图规则（2026-10-16 更新）

默认每格 **2 张**，普通绘制、单格重画和导入提示词共用数量选项。普通绘制先显示逐格正负提示词，可手动修改，点击「确认原样出图」才开始。没有有效提示词时必须填写或导入，后台不会调用本地语言模型生成、翻译、改写或自动接受提示词。确认的文本与 LoRA 保存为任务快照，原样传给绘图工作流；触发词需由用户写入提示词。

**不再自动审核或补画**。失败只记录，继续处理其余已计划的图片；不因 AI 判退重复出图。旧图片、审核记录和选图均保留，旧待审核图片也能手动选用。暂停继续沿用同一任务快照。旧版自动审核补画任务不再允许恢复；已结束任务不会因修改默认值自动启动。模型对照不再自动升级旧提示词，局部修复不再附加自动审核，全自动流程在文字分镜保存后停止，等待用户核对提示词。

旧版本的分阶段审核、16 张候选和自动补画说明仅作为历史记录，以本节规则为准。

## 分镜与外部提示词文件（2026-10-16）

导出 JSON 顶部包含给 Grok 等外部工具的任务说明、五步处理流程与逐格编写规则：先读完整分镜再逐格写英文提示词；避免所有画格重复长段背景和人物介绍，同时保留每格独立出图所需的简短身份信息；明确人物特征归属、动作瞬间、道具数量、镜头差异及返回格式。默认仅填写正负提示词，保留原始分镜与标识；导入仍原样使用用户确认的文本。

确认全部分镜后，在第二步点击「导出分镜给外部工具」，或在第三步「外部提示词」导出 JSON。文件逐格包含人物资料、动作、场景、镜头、对白，以及空白的 `positive` / `negative` 字段和填写说明。可以把文件交给外部工具填写，保留 `format`、`project_id`、`storyboard_hash`、`panel_id`、`page_id`；只处理部分画格时可移除其他条目。

第三步导入返回的 JSON 后，先核对逐格正负提示词，再确认保存。重复/不存在的画格、空正向提示词、错误作品或旧分镜会拒绝导入；漏格会明确列出，只绘制实际导入的部分。导入版本保存在作品的 `prompt-imports/`，不会替换已确认分镜或本地绘图描述。

「按导入提示词绘制」与普通漫画绘制共用左侧的「每格生成数量」（1/2/4/8/16，初始 2 张），可选择单格或全部已导入画格，并调整模型、步数、种子。每张图加载第一步保存的 LoRA：全图风格用于每张图，角色 LoRA 按本格出场人物匹配，仍遵循「不用 LoRA／仅使用勾选项／自动匹配出场角色」设置。任务开始时冻结逐格 LoRA 与权重，暂停继续沿用快照；旧任务没有 LoRA 快照则保留原有无 LoRA 行为。提示词保持原文，所需触发词应写入导入文件；不附加角色词、画风词、镜头词、参考图、手部增强或动作条件，不调用本地语言模型改写，也不自动审核补画。已有图片与选图保留；同一任务暂停后继续会复用已保存候选。旧任务处于暂停状态时，须先继续或取消旧任务才能发起新绘图，导出和导入不受影响。

## 任务控制与选图界面（2026-10-16）

分镜生成出错后，顶部任务卡提供「重新生成当前出错页」。点击后从已有草稿的断点继续，跳过已保存页面，并完成剩余页面与集中核对。已确认的内容不会被自动覆盖。作品已修改或断点文件缺失时会提示原因，避免从头重做；同一失败任务不会重复提交。

顶部任务栏提供暂停、继续和取消。暂停与取消均在当前图片或文字保存后的工作边界生效；取消必须再次确认，已生成图片、选图和剧本保留。暂停任务不会自动恢复。整部/单格绘图的任务请求保存到本地，服务重启后可显式继续，复用与当前分镜和画风匹配的图片；剧本或绘图设置变化会拒绝沿用旧任务。

选图位于中间主区域，当前画格最多 16 张候选全部展开，不再每 4 张翻页。未审核图显示明确标识，可由用户自行核对后选用，原审核状态保留；旧版分镜图仍不能用于当前分镜。共用的「每格生成数量」放在左侧两个出图入口上方，采样步数和起始种子仍在「高级选项」，只影响新任务；默认改为 2 张，不改动暂停任务的数量。左侧显示画格数与首轮候选数量的计算方式，排版入口折叠在选图区下方。

输入中文故事需求和角色资料，分阶段确认剧本与文字分镜，再交给 ComfyUI 生成二次元漫画候选图。当前默认绘图模型为 **Anima 3.8B v1.1 / ComfyUI**，Sudowrite 暂不启用。

这是独立项目，全部创作数据、模型和 Python 环境位于本目录，编剧部分不依赖旧对话文件夹。Anima 使用本项目的 `runtime/ComfyUI-Anima` 与 `.comfy-venv`，可在 `config/comfyui.json` 改路径。

Anima 的主模型、Qwen3.5 4B、Qwen3 0.6B 和 VAE 共约 15.03 GB，固定文件哈希在 `config/anima-model.json`。角色权重位于 `models/loras/anime/`：2026-10-15 已核验下载方舟 37 个、原神 80 个。Anima 基础版 LoRA 通过专用补丁映射到 3.8B 的 52 层；并非全部直接在 3.8B 上训练。来源、训练底模与 SHA-256 见 `data/anima-migration/coverage.json`，未找到的角色见 `data/anima-migration/missing-characters.txt`。

Anima 推理使用 CUDA，闲置编码器卸载到内存，避免 24 GB 显存下全部组件常驻导致采样缓慢。Anima 不使用现有 SDXL 的 IP-Adapter、ControlNet、区域 LoRA、高清二次采样及手部修复流程；界面会停用不兼容的选项。多人位置请写进提示词。旧作品中明确保存的模型选择仍按作品设置加载。

当 Anima 正向描述同时包含躺姿、弯膝踢腿、朝向镜头或前景的脚、2.5D 和微恼表情时，后台自动使用动作构图条件：前段优先完整的腿脚轮廓，后段恢复完整原文条件，沿用同一次采样及原来的种子、尺寸和参数。没有新增界面控件，其余描述沿用原流程；实际早期条件记录在批次 `action_conditioning` 和工作流中。2026-10-15 两个历史种子对照已完成，脚部均未裁切，但躺姿仍会偏成坐姿，尚不能保证动作完全准确。记录位于 `data/anima-migration/kick-verification/final-1` 和 `final-2`。

`archive/legacy-launchers/13-download-anima.bat` 可续传并核验权重，日志在 `data/anima-migration/`。原默认配置备份在 `data/anima-migration/comfyui-before.json`。已完成纯底模和甘雨 LoRA 的本机 GPU 出图测试，记录在 `data/anima-migration/gpu-verification/`；其他角色已核对文件与结构，未逐个进行视觉还原度评测。

## 开始使用

双击项目根目录 **`LocalDraw.exe`**。从故事生成 POV 分镜，确认并导出 JSON，然后逐格填写提示词、绘图和选图。关闭窗口后，已提交的生成任务继续在本机执行，再次打开可点「查看生成任务」。双击 EXE 会激活已有窗口。

1. 在“剧本与角色”粘贴一段故事或想法，选择整理、扩写或续写。标题、题材、故事方向由 AI 整理；页数等只需有偏好时填写。
2. 在同一入口新建角色：可用“图片＋性格”让本机 Qwen 识别外观，也可用文字生成详细角色卡。核对后保存，之后用 `/角色名` 引用，例如 `/林晴`。角色卡保存历史版本，已有作品锁定引用的版本。
3. 检查 AI 剧本草稿并确认，直接进入“逐格分镜与对白”。世界观和多个剧情方案不再是操作步骤；程序只从剧本整理必要人物、场景与状态。再次扩写旧作品会另建作品，保留原作。
4. 第二步点击“一键生成全部缺失分镜”。先一次生成整部草稿、集中核对，再统一确认、逐条修改。已确认页保留；修改稿按画格显示卡片，右侧 Apply / Cancel，应用某条不会改动其他格。
5. 第一步选择 LoRA 和保存的画风。第三步“一键绘制全部画格”：先准备全书描述，再每格生成 **16 张候选**，全部出图后集中审核，最后集中补画。16 张使用六种允许的构图与不同种子，不保证模型呈现 16 种不同角度；显卡仍单图运行，模型按阶段驻留。
6. 单张生成或审核报错会记录原因、继续其他图片，最后重试；审核出错只重审已有图。每槽位最多三次绘制（首次加两轮补画），不无限循环。明确不符保持淘汰，不确定保留供人工核对；达到上限的缺图如实列出。已提交但无法确认结束的任务不会重复排队；原稿或设置发生冲突时保留结果并报告。
7. 每格选一张，选择立即保存且页面不跳顶。重新打开恢复上次步骤、展开项、滚动位置、修改意见与编辑草稿。排版默认窄间距、大小格和铺满裁切；可设 `fit: contain` 保留完整画面、`focus: [0.5,0.5]` 调整裁切中心。对白用椭圆气泡与短尾，旁白用文字框，拟声不套气泡。导出 PNG、可编辑 SVG 和独立文字层；仍须人工核对遮挡和气泡指向。

第三步提供“查看失败图与原因”和“查看画风对照”，失败图片会保留且可打开原图。每格可先生成两张小样，对比镜头修正与构图草图控制；草图控制仍是实验项，不默认用于整部。图片旁的“框选错误区域修复”只改所框区域，新图另存并重新审核，原图与选图历史保留。画风方向与已知问题见 [彩色叙事漫画方向](docs/ART_DIRECTION.md)。

第二步默认只显示可读分镜与一句话修改入口，编号、状态等表格收进“高级编辑”。任务顶部显示预计剩余时间；进度条只表示真实完成量，包括已处理格数、当前轮图片数、模型输入处理量和绘图采样步数。文字输出显示实际 token 数和速度，总长度未知时不编造百分比。剩余时间依据实测速度和同类任务历史估算，无数据时明确显示暂不能估算。出错时保留已完成图片、错误原因和进度，可继续未完成画格。

角色图片识别使用已有 Qwen3.6-27B 加配套 F16 视觉投影模块；视觉编码在 CPU 上运行以控制显存。普通文字任务不必加载视觉模块。整理剧本、建角色和新版出图会按需启动模型。整理剧本和角色建档生成结束后自动卸载语言模型及已加载的视觉模块，加载、生成或保存失败时也会清理。图像审核任务结束时卸载本次模型和本项目 ComfyUI。

LoRA 放在 `models/loras`，支持子目录和中文文件名。在界面标注名字、设置触发词和权重，可选择“手动勾选”或“按本格角色自动匹配”。软件检查 safetensors 结构，SD 1.x LoRA 不可用于当前 SDXL 底模；文件会保留。不会训练 LoRA。

直接提示词出图和正式漫画出图默认启用“自动增强手部”，可在出图设置关闭。使用 [ADetailer 发布者提供的手部检测模型](https://huggingface.co/Bingsu/adetailer) 在 CPU 上检测手部，再用当前 SDXL 底模局部放大细化，最多四个区域；相接的手部合并处理，画布尺寸保持不变，增强前原图单独保存。没有训练或替换底模权重。没有检测到手、细化失败时保留原图并记录状态；任务状态未确认时停止后续提交。模型对照试画和手动框选修复不叠加自动增强。该流程还没有做新的生成效果验证，不能保证手指结构正确。

参数位于 `config/hand-detail.json`，全局默认开关在 `config/comfyui.json` 的 `hand_detail`。检测模型为 `models/hand_detection/hand_yolov8n.pt`，启动和出图不会自动下载；检测依赖使用 `.comfy-venv/Scripts/python.exe -m pip install -r config/hand-requirements.txt` 安装。每张图的增强记录、裁切、蒙版与局部工作流保存在其图片文件夹的 `hand-detail-*` 目录，`base-*.png` 是增强前原图。

第一步的 LoRA 区域提供三张带样图的画风卡：**左·原生画风 / 中·方舟 LoRA / 右·方舟 LoRA＋角色参考**。中间使用现有方舟样式 LoRA 0.7，右边另加角色图像参考 0.7；右边是组合预设，不是新训练的 LoRA 文件。三套沿用对照图的 Animagine XL 4.0 Opt、28 步、CFG 5。选择随作品保存，参数手动改动后显示为“自定义”。切换画风保留历史图片和用户选图，新画风不复用旧画风的失败次数。样图用于说明画风，不能保证不同剧情具有完全相同的成图质量。

详细新增功能和边界见 [角色、剧本与图像审核说明](docs/CREATIVE.md)，实际通过与未通过的结果见 [新增功能验收记录](docs/FEATURE_ACCEPTANCE.md)。

中文 Markdown 和 JSON 从同一确认版本导出；JSON 是正式数据源，Markdown 是阅读副本。直接改导出的 Markdown 不会静默覆盖作品，请回到编辑器提交候选。

## 常见情况

- **模型启动失败**：看 `data/logs/model-server.log`。先关闭其他占显存的任务。不要盲目提高上下文或并发。
- **ComfyUI 启动失败**：看 `data/logs/comfyui.log`；确认 `config/comfyui.json` 中软件路径正确。用项目环境运行，不使用旧的缺少 PyTorch 的环境。
- **候选校验失败**：原始模型输出与错误保存在作品 `runs/`，不会覆盖已确认版本。修订提示或在编辑器整理后再提交。
- **上下文预算不足**：缩短资料、分阶段维护必要状态；程序不会截断已确认剧情来硬塞入上下文。
- **绘图超时/重开中断**：检查 ComfyUI 队列与作品图片批次记录，避免重复提交尚未结束的任务。已完成图片与选图保留。
- **界面显示模型已就绪但不能卸载**：有非本工作室启动的模型进程；关闭那一个进程后，从工作室启动，才能由界面管理。

# 三个模型下载与少量试画（2026-09-19）

## 详细绘图说明与模型适配

Qwen 先依据原文、角色资料和分镜，编写中文画面说明、必须出现的细节、动作与物体关系及未知事项，再转成英文视觉标签和短关系描述。详细指人物外观、位置、可见动作和道具接触关系明确，不以堆积修饰词或编造剧情增加长度。每格仍只画一个主要瞬间。

提交绘图时按实际底模调整标签：Animagine 4、Animagine 3.1、NoobAI 1.1 和 Illustrious 2 分开处理；未收录的模型不猜专用标签。模型卡来源保存在 `src/comic_workflow/prompt_adapter.py`，Illustrious 使用项目的保守配置，尚未实测优化。LoRA 触发词保留。少量对照共用一份情节描述，由各底模适配标签；整部制作先集中准备需要更新的描述，再批量出图和审核，避免为每张图切换 Qwen。

第三步每格可展开「AI 绘图说明与提示词」。新图片在「原因 / 修复」内可查看实际发送的正负提示词和模型。旧描述在下次用户发起相关绘图时更新，不重写旧图；版本历史保留。这是提示指令和转换程序的改进，**没有微调 Qwen 权重**；画质、角色符合程度及良品率须真实对照验证，不能用离线测试代替。

角色外观框只用于可见外观。粘贴带 Personality、Speech Style、Interaction Guidelines 等章节的聊天角色卡时，界面和后台会阻止直接绘图，避免性格、对白和人物关系混入画面。点击「整理 / 转换英文提示词」可整理已有英文或翻译中文；场景明确指定的服装优先于角色卡的默认服装，整理结果可核对和恢复。「重置为角色外观资料」只恢复外观字段，不改角色卡。参考图随角色选择默认启用，可逐个角色取消，并使用各自的画面位置，例如只让博士使用右半边的参考图，阿米娅的女仆装由文字控制。旧试画记录与原图保留；这些输入控制不能保证每张图的人数和外观都正确。

多人选择明确、不重叠的位置后，可开启「按画面位置分区绘制人物外观」。场景描述作为全局输入，每个人的外观分别编码并限制到所选区域；预览显示全局场景与各角色区域。这个开关不改写文字，也不保证人物位置、人数和接触动作完全正确。旧记录默认保持原来的整体提示词方式。

左侧「管理作品 · 多选删除」支持搜索、全选当前结果、取消全选和批量移入回收站；删除前显示数量并确认。批量删除会先核对全部作品版本，防止只删除部分选择。运行中的作品也可删除，任务继续执行并保存结果；暂停和待确认状态保持不变。回收站显示任务状态，可刷新进度、暂停、继续或恢复作品。回收站可恢复作品及图片，移入回收站不释放磁盘空间。

提示词出图的图片预览顶部提供「复制当前图片」和「复制所有图片」。当前图片随预览切换；所有图片以独立 PNG 原图复制，可粘贴到文件夹或支持多文件粘贴的软件。单张同时提供图片剪贴板格式，方便粘贴到图片编辑器。复制缓存独立于出图会话，刷新页面后仍可粘贴；剪贴板内容被替换后自动清理，不加入作品历史。正向提示词旁提供「粘贴」，插入到光标位置或替换选中文字。
