# 架构与维护

本项目是可移动的本地 Python 应用，前端使用原生 HTML/CSS/JavaScript，不依赖 Node 构建、CDN 或在线字体。Windows 入口以自身位置定位根目录。源码依赖使用项目 `.venv`；ComfyUI 使用独立 `.comfy-venv`，避免 PyTorch 污染编剧服务。ComfyUI 软件路径来自 `config/comfyui.json`，当前为已有的 `E:/AI/ComfyUI`，没有任何旧对话目录运行依赖。

## 文件职责

- `src/comic_workflow/engine.py`：合并候选、编号/引用/状态校验、Markdown 导出。
- `schemas.py`：唯一 Schema 定义；`scripts/export_schemas.py` 生成根目录 `schemas/`。
- `repository.py`：作品、草稿、候选、历史、分支和同版本导出。
- `model.py`：Qwen 上下文裁剪、实际 token 预算、结构约束输出和模型进程管理。
- `comfyui.py`：仅通过 ComfyUI 本机 API 提交、等待、回收图片和选图，不依赖选图自定义节点。
- `layout.py`：从明确选择的图片生成页面 PNG、可编辑 SVG 和独立文字层。保留图像比例，默认留白，不自动裁掉人物。
- `server.py`、`jobs.py`：本机界面 API 与持久化任务记录。
- `automatic.py`：显式授权的整部制作、原文分页与独立文字保留、逐页检查点和结束清理。
- `character_binding.py`、`visual_policy.py`：冻结角色版本绑定、留痕的遮脸取景修正。
- `reference_images.py`：原参考图条件、多人软区域及实际工作流接线。
- `reviewed_drawing.py`、`batch_drawing.py`：六视角、图文对照、限次补画和整部进度。
- `sudowrite.py`：暂不启用的文档交接适配，不是 Sudowrite 私有 API。当前写作引擎为 Qwen。

## 数据与确认

`data/projects/<作品编号>/project.json` 是当前确认版本。草稿放 `drafts/`；候选放 `candidates/`；旧版放 `history/`；请求和原始响应放 `runs/`。每份候选绑定整个基础版本的 SHA-256。即使只改一格，版本变化也会使旧候选过期，避免覆盖其他刚确认的工作。

确认时先保存旧版，原子替换 `project.json` 作为提交点。进程锁避免两套界面服务同时写入同一数据目录；线程锁串行化确认。模型任务耗时操作放后台，失败原始响应可查。重开应用时未完成任务标为中断，已确认作品和选图不丢失。不做无提示自动重试绘图，以免对已经排队的 ComfyUI 任务重复提交。

上游设定已有下游内容时，改动需创建分支。分支只清理新作品的下游，原作品保持完整。改一页保持出入状态；改一格保持该格末状态，并保护其他格及其独立文字。这是边界保护，不是语义正确性的证明。

`drawing_prompts` 为指定绘图模型的英文适配，绑定中立分镜内容哈希；分镜改变之后旧适配不能出图。`images/index.json` 保存批次、模型、配置、种子、图片、状态和明确选择；选择变化也保留历史。`layouts/<批次>/` 是不覆盖的排版快照。

## Markdown 与 JSON 一致性

在网页结构化编辑器或 JSON 编辑器修改，提交候选后再确认。每次导出生成新的 `exports/<版本-批次>/`，同时写 `script.json`、`script.md` 和 `manifest.json`，后者记录确认版本哈希。Markdown 只用于阅读，不反向静默解析。若在外部改了 Markdown，需要回到编辑器转成候选；不会有两个彼此冲突的正式源。

## 连续性检查的范围

硬错误：必填字段缺失、页格遗漏/重复、未知角色/场景/道具/文字编号、说话者错误、气泡顺序跳号、分页与阅读方向矛盾、跨页状态边界不匹配。

启发式提醒：对白过长、连续同景别、左右变化、道具未入镜、疑似一格多动作、纸质跨页提前揭晓。提醒可能是正常取景造成，需结合画面人工判断。角色口吻、原作事实和真实因果由逐页 AI 审核辅助，不能机械保证。状态键目前使用可编辑完整快照；页面上下文只带相邻分页、必要角色/场景、前页末格与当前状态，避免全书反复输入。

## 扩展约定

新的模型适配写独立模块，不把模型专用标签混入原始 `drawing_description`。LoRA 必须记录底模、版本、触发词、权重与来源并实际验证；不会把 Anima、SDXL 和 Qwen 的 LoRA 互换。已实现标准 SDXL LoraLoader 接线和触发词/权重记录。参考图编辑和超分是后续独立适配，不能冒充当前已完成能力。

后续已有本机画风 LoRA 出图测试，详见 `FEATURE_ACCEPTANCE.md`，它们并非角色专属 LoRA。参考图现通过固定版本 IP-Adapter Plus SDXL 节点注入，不能等同于局部编辑或精确身份保证。

构造模型生成 Schema 时使用 JSON 序列化往返拆开共享字段对象，再加具体字段的编号范围和长度限制；普通 `deepcopy` 会保留共享引用，不能用于这个用途。回归测试检查编号范围不会泄漏到其他文字字段。角色库 UUID 若被模型误用为剧本角色编号，只在名字明确匹配时转换并留日志，未知编号仍拒绝。
