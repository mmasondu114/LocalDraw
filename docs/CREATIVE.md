# 剧本、角色库、自由分格与审核

## 操作入口

主界面只有三步：**剧本与角色 → 逐格分镜与对白 → 绘图与排版**。旧项目的世界观、方案和大纲数据仍保留用于兼容；新建作品不要求用户逐项操作这些阶段。

“剧本与角色”可直接粘贴故事。整理模式逐字保留原文段落和顺序，由 AI 指定场景标题位置并提取人物、场景和详细情节索引，程序拼接正文，避免让模型重述全文时删掉细节。正文不占模型输出额度；场景编号必须从第一段开始、严格递增且不越界，否则拒绝草稿。扩写模式补细节/对白，续写模式延伸后续。AI 输出完整剧本和它做出的假设；先审核再创建作品。剧本手工改过时，会重新抽取人物和场景并要求再确认，避免故事与内部资料失配。新整理旧作会另存作品，不覆盖原作。

创作输出统一使用英文：用户提供英文原文，整理时不额外翻译，逐字保留正文；场景标题、角色卡说明、资料、大纲、扩写/续写、原始分镜描述、对白、旁白、拟声、绘图说明和审核意见均要求英文。机器编号、枚举值、已有状态键及角色库检索名仍保持引用一致。界面操作说明仍为中文，旧作品不会自动翻译或覆盖。英文分镜描述上限为 1400 字符，避免沿用原来的 200 中文字符额度截短细节。

## /角色名

角色名本身就是引用名，例如 `林晴` 对应 `/林晴`，支持中文。输入 `/` 可选择已保存角色，选择后自动插入空格。也支持中文紧接角色名的常见写法，匹配最长的已保存名字；有歧义时请用空格或标点分隔。未知名字会提示先建档。

两种建档方式：

- 图片＋性格：上传 PNG/JPG/WebP，最多 10 MB、2400 万像素；规范化为最长边 1024 的本地 PNG，去掉 EXIF 等附加信息。图像只用于识别外观，性格、身份、经历依据用户文字；遮挡部位写未知。
- 详细文字：输入资料，AI 按五官、发型、眼睛、体型、服装、配饰、配色、辨识特征、性格、口吻、动机、经历、关系和禁区展开成可修改卡片。AI 新补内容与未知项单列。也可直接手工填写完整卡片保存。

角色图和卡片在 `data/characters`，每次保存建立新版本。作品的 `brief.character_refs` 保存引用快照；更新角色库不会偷偷改已确认作品。图像识别不会训练 LoRA，也不把图像直接当作绘图身份条件。

角色编辑界面只保留一个大资料框：外观、性格和背景等一起填写，AI 草稿也回到同一个框中。生成后可直接修改各段内容；保留段落标题即可直接保存。若改成无分段的自由文字，保存时会先重新整理为待确认草稿，不会直接覆盖已保存角色。角色名、参考图和建档方式仍单独选择，底层结构与历史版本保持不变。

视觉模型沿用 Qwen3.6-27B，配套 `models/vision/mmproj-F16.gguf`，文件 927,607,360 字节（约 0.928 GB / 0.864 GiB）。SHA-256：`eacf610d1ee4bd5ed0197a0777dd8f4fceb8eefa27009067c7d496cb68fbde45`。[官方分发文件](https://huggingface.co/unsloth/Qwen3.6-27B-GGUF/blob/main/mmproj-F16.gguf)；[llama.cpp 多模态接口](https://github.com/ggml-org/llama.cpp/blob/master/docs/multimodal.md)。编码器使用 CPU，写作权重仍在 GPU；只有看图时需要该模块。

## 大小分格

新剧本默认 `panel_mode=flexible`，每页 1–9 格。已生成分镜的 `layout_rows` 描述按阅读顺序排列的行、高度权重和格宽权重；程序将其转换为真实像素矩形。RTL 由程序镜像排格，不反转内容编号。

页面可切换“按分镜节奏”“首格大画面＋细节格”“宽窄交替”“均衡分格”“竖向条漫”，即时显示排版预览。旧的等大分格仍可选择。当前支持矩形漫画格，不支持斜切格、跨格人物和无边框混排；选图默认完整容纳、不裁切。

## 六视角与自动补画

每格一次请求生成六个不同镜头的英文画面描述，并串行生成六张图。用户文本指定的动作、角色、服装、道具和空间关系优先于角度变化；若文本锁死角度，则在允许范围变化取景距离与构图。模型可能未完全执行镜头要求，不能仅凭六条不同提示词断言六张都完全符合。

随后卸载绘图模型，使用本机 Qwen 视觉模块对照该格文本及剧本背景逐项审核。不是审美评分：

- `pass`：AI 认为关键项可确认，仍由用户选图。
- `reject`：有明确不符项，保留历史但退出候选且不能选用。仅补生成被拒绝的视角，已经通过的视角不重画。
- `uncertain`：看不清或有歧义，标记待人工核对，不伪装为通过。
- `pending`：审核尚未完成，禁止选图。任务失败时保持此状态。

最多补画两轮，每个视角合计最多三次。到上限仍不符会保留失败原因，暂停等待用户调整文字、模型或 LoRA。不会无限循环占用显卡。补画和审核不自动选图、不改分镜，不删除淘汰图。每次任务保存图、实际工作流、审核原始响应和补画报告。

AI 可能误判。当前不宣称“严格百分之百一致”；用户最终选图是人工确认。图库显示完整审核理由，未审核的老图明确标记。实际审核中可能全部淘汰，这属于真实结果，不能将失败图片强行通过。

## LoRA 名字与兼容性

文件放在 `models/loras`，可用子目录分类。第一步显示 LoRA 名字，可批量勾选并应用到整个剧本或指定的多个角色，允许修改名字、触发词、权重。支持不用 LoRA、手动选择、按本格角色匹配三种模式。每格最多四个兼容 LoRA 叠加，全剧本与角色范围合计计算；超限在整部任务开始前提示。

作品配置保存在 `data/projects/<作品>/drawing-settings.json`，更新前保存历史，不改变剧本确认版本。新作品尚未创建时暂存在浏览器，确认剧本后写入作品。第三步自动读取这份配置；任务开始时固定本次应用范围，进行中的任务不会因为设置变化而混用参数。全局标注仍在 `data/lora-labels.json`。

按角色应用指该角色出场的整格启用 LoRA，不是对图中单个人做区域隔离；多人同框的多个 LoRA 可能互相影响。

## 角色身份与参考图的实际边界

绘图适配和画面审核使用同一份作品内保存的角色卡版本，按角色编号绑定身份、作品背景、外观和服装。通用称呼不能替代作品身份；例如明确指定《明日方舟》博士时，提示词必须保留作品限定及兜帽、面部遮蔽等已知特征。每张候选实际输入 ComfyUI 的描述都会带入角色外观标签；角色资料变化后，旧绘图描述需要重新生成。旧图片及用户选图不会自动删除。

参考图经 IP-Adapter Plus SDXL 和 CLIP ViT-H 接入 ComfyUI；实际工作流、参考图文件指纹、权重均随批次保存。多人同框按分镜的左右位置设置柔和注意力区域，位置未知时分区；这是参考影响范围，不是精确人物分割，也不能保证服装、脸或多人关系正确。视觉审核把候选图与对应角色原参考图一起输入，明确区分候选与参考，不要求复制立绘姿势或背景。角色 LoRA 需要对应角色和底模；画风 LoRA 不能作为人物身份保证。

双击 `08-download-reference.bat` 可安装固定提交的参考图节点并断点下载两个组件，完成后校验 SHA-256。来源及文件大小、校验值记录在 `config/reference-models.json`。只允许这个项目内固定的自定义节点，未开启其他自定义节点。

## 授权后的整部自动制作

`automatic` 应用任务支持已经按页、格写好的原文：按正文实际分页建计划，保留每格原对白、旁白和拟声，生成分镜后保存版本，再逐格画六个视角、审核及限次补画。启动必须携带明确的自动确认授权；最终图片不自动选择。原文运行中变动会停止。中断后同一份原文可继续已有分镜和图片；记录在作品的 `runs/<任务>/automatic.json`。这不是把 AI 审核当成人工确认。

本次《苹果派与封锁线》正文实际有六页，优先于开头的四页建议；角色卡外观优先，博士保持遮脸，通过手部、背影或画外动作表达进食，原事件和对白保留。此取舍在作品自动制作策略中留档。

自动任务结束或失败都会关闭本项目拥有的语言、视觉与 ComfyUI 推理进程以释放显存，保留网页、图片、模型文件和历史版本。桌面及其他应用的显存不属于本项目，不会强制关闭。

## 分镜自动修正的上下文预算

对草稿的结构校验失败时，最多自动修正一次。使用实际 tokenizer 计算输入和输出预留；重试历史过长时，移除未确认失败稿，保留完整原始资料和错误说明重新生成。没有删减已确认剧情，也没有提高显存或上下文配置。输入 JSON 去除无用缩进，连续性审核不重复携带同一页，审核输出预留最多 3500 token；气泡顺序在每格内从 1 重新编号。审核未能完成时，可以只重试审核，另建内容相同、附带新审核结果的候选，不必重写分镜。原始资料本身仍超过容量时明确停止，不偷偷截断故事。

## 一键绘图和进度

整部任务续跑会复用相同分镜、角色身份、底模及 LoRA 的已保存图片，先补做未完成的审核；已通过/不确定图片不重复审核。每个视角最多生成三次，次数跨服务重启累计，达到上限的格子不会因整部续跑而无限补画。仍不符合的视角单列为未解决，只有用户明确单格重画才开始新的尝试。保存进度遇到 Windows 短暂文件占用时会有限重试，持久故障仍停止并保留旧记录。

确认所有分页后，第三步“一键绘制全部画格”按页、格顺序依次运行六视角生成、文本审核及有上限的补画。已选图保持不变；同版分镜、同模型和同 LoRA 配置已有六个可用审核视角时跳过。绘图故障时停止追加任务，保存已完成部分和错误报告，避免把未知状态的绘图任务重复提交。分镜在绘图期间变化时也会停止。

总进度按已处理格数计数，不代表所有图均通过；每格达到补画上限也会处理下一格，并明确列出仍不符的视角。环节进度按当前轮绘制/审核张数计数，重试会开始新一轮。进度条没有循环动画，只随实际完成数变化：输入处理读取 llama.cpp 回报，绘图读取 ComfyUI 当前节点和采样步数。文字生成显示实际 token 数、生成速度；不知道最终长度时不显示虚构百分比。

预计剩余时间位于任务顶部；整部绘图根据同类已完成画格（包含审核和补画）的实测耗时估算，单次采样按近期步骤速度估算，文字输出按同类输出长度历史与实时速度估算。估计会随速度、文本长度及补画次数变化；没有数据时显示暂不能估算，超出估计时明确提示。加载权重没有真实总量时只显示正在执行的步骤，不制造进度。任务记录在 `data/jobs`，重新打开界面可恢复显示；服务重启会将未完任务标为中断。

候选图片按格显示为单选卡片，点击即保存，每格只能选一张。未审核和拒绝图片不能选择；不确定图片需要用户重点核对；历史图片保留，旧版分镜图片不能用于新版。排版仍在选图后由用户启动。

读取 safetensors 文件头、架构声明及交叉注意力维度，不执行权重文件代码。结构不兼容的禁用；SDXL 内不同训练底模即使能加载，效果也可能不同。实际加载测试只证明节点工作流成功出图，不证明角色或画风完全正确。

## 验证

故事保真整理分为角色资料和故事结构两次调用，每次输出上限为 9000 token，两次均读取完整原文。生成角色资料时，来源、事实、改编选择、未知项、台词示例和禁忌各最多三项，每项最多 240 字符；外貌、口吻和动机各最多 500 字符。保真整理模式的来源引用只能从实际原文段落编号中选择，每个角色最多三条，避免来源字段无限列举数字。这些限制直接用于约束生成和结果校验，不限制或截短原文；共享的作品保存结构保持兼容。模型未完成时报告实际结束原因和输出上限，不再一律提示用户缩短输入。

`06-test-offline.bat` 覆盖角色版本/名字/引用、图片上传、自由格数与 RTL、直接剧本、LoRA 架构、拒绝图片禁止选择、仅重画被拒视角、补画次数上限。

`scripts/test_features_live.py` 是显式手动触发的真实测试，结果在 `data/test-results/features-live`；`scripts/test_loras_live.py` 实测本机兼容 LoRA，结果在 `data/test-results/lora-live`。普通启动不会执行这些测试或下载模型。
